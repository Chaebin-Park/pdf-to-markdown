# 읽기 순서 편집기 설계

## 문서 상태

- 상태: 구현 전 설계 확정안
- 작성일: 2026-07-20
- 대상 버전: v0.10 후보
- 구현 여부: 미착수
- 상위 원칙: `DESIGN.md`

## 1. 문제와 대표 사례

자동 변환은 문단의 좌표, PDF 구조 태그, 다단 레이아웃을 이용해 읽기 순서를 추정하지만 모든 문서를 완벽하게 판단할 수 없다. 특히 본문 옆의 보충 문단, 캡션, 각주처럼 세로 위치가 겹치는 블록은 사람에게 자연스러운 흐름과 다르게 배치될 수 있다.

대표 사례의 자동 결과는 다음과 같다.

```text
6 → 7 → 8 → 9 → 10
```

사용자가 기대하는 흐름은 다음과 같다.

```text
6 → 7 → 9 → 8 → 10
```

변환 알고리즘의 선택지만 늘리는 것으로는 모든 예외를 해결할 수 없다. 따라서 자동 판단을 기본으로 유지하되, 사용자가 결과를 눈으로 확인하고 페이지 안의 블록 순서를 직접 교정할 수 있어야 한다.

## 2. 목표

1. 현재 `Order` 표시 기능을 읽기 순서 확인·편집 진입점으로 확장한다.
2. 사용자가 페이지 안의 최상위 콘텐츠 블록을 드래그 또는 키보드로 재배치할 수 있게 한다.
3. 한 번의 순서 변경을 Markdown Preview, Source, Copy, Save와 구조 기반 부가기능에 동일하게 반영한다.
4. 원본 자동 판단을 보존하고 변경을 취소·되돌릴 수 있게 한다.
5. 일반 사용자에게 알고리즘 용어를 요구하지 않는다.

## 3. 비목표

- PDF 원본 파일의 시각적 배치 변경
- 문장, 글자, 표 셀, 목록 항목 단위의 세부 재배치
- 첫 버전에서 페이지를 넘나드는 블록 이동
- 변환 후 생성된 임의의 Markdown 문자열을 역파싱해 구조를 추측하는 방식
- 공동 편집, 변경 이력 공유, 주석 시스템

## 4. 범위 결정

### MVP 편집 단위

- 한 페이지 안의 최상위 블록만 이동한다.
- 대상 형식은 heading, paragraph, table, list, image, formula다.
- 표의 행·셀, 목록의 항목, 문단 안의 text chunk는 부모와 함께 이동한다.
- 페이지 경계는 고정한다.

이 범위는 현재 Order 오버레이가 이미 최상위 형식에 번호를 표시한다는 점과 맞고, 구조 파손 위험을 제한한다.

### 후속 후보

- 다른 페이지로 이동
- 부모/자식 구조 편집
- 여러 블록 묶음 이동
- 자동 순서와 사용자 순서의 시각 비교
- 잘못된 자동 판단 사례를 로컬 진단 자료로 내보내기

## 5. 사용자 흐름

### 기본 흐름

1. PDF를 변환한다.
2. 사용자가 `Order`를 누르면 감지된 읽기 순서가 번호와 연결선/강조로 표시된다.
3. `순서 편집`을 누르면 현재 페이지의 블록이 편집 가능 상태가 된다.
4. 사용자가 9번 블록을 8번 블록 앞으로 드래그하거나 키보드 이동 명령을 사용한다.
5. 번호가 즉시 `6 → 7 → 9 → 8 → 10` 흐름으로 다시 매겨지고 오른쪽 Markdown이 갱신된다.
6. 변경 페이지에는 `수정됨` 표시가 붙는다.
7. 사용자는 편집 모드를 종료한다. 변경은 현재 결과에 유지되며 Copy와 Save도 같은 결과를 사용한다.

### 되돌리기 흐름

- `실행 취소`: 마지막 이동만 되돌린다.
- `이 페이지 원래 순서로`: 현재 페이지의 모든 사용자 변경을 자동 감지 순서로 복원한다.
- `모든 페이지 원래 순서로`: 문서 전체 변경이 있을 때만 제공하며 확인을 요구한다.
- Escape: 진행 중인 드래그나 선택만 취소하고 이미 적용된 이동은 보존한다.

## 6. 화면 및 상호작용 설계

### 보기 모드

- 기존 `Order` 버튼을 누르면 번호 오버레이를 표시한다.
- 기술 용어 대신 툴팁을 `읽기 순서 표시`로 유지한다.
- 순서가 변경된 페이지는 페이지 번호 옆과 Order 상태에 `수정됨` 배지를 표시한다.

### 편집 모드 진입

- Order 보기 상태에서 `순서 편집` 버튼을 노출한다.
- 진입 시 짧은 안내를 한 번 제공한다.

```text
문단을 끌어 순서를 바꾸세요. 미리보기와 저장 파일에 바로 반영됩니다.
```

- 안내에는 `키보드로 이동` 도움말 진입점이 포함된다.

### 블록 표현

- 각 최상위 블록에 순번, 형식, 짧은 텍스트 미리보기, 드래그 핸들을 제공한다.
- PDF 위에서는 번호 칩과 블록 경계를 표시한다.
- 좁거나 겹치는 블록을 정확히 선택할 수 있도록 현재 페이지의 순서 목록을 보조 패널로 함께 제공할 수 있다.
- 번호는 현재 위치를 뜻한다. 원래 번호를 영구 식별자로 사용하지 않는다.

### 드래그

- 블록 자체 또는 드래그 핸들에서 시작한다.
- 유효한 삽입 위치를 블록 사이 선과 `8 앞에 놓기` 같은 접근 가능한 문구로 표시한다.
- 드래그 중 PDF 자동 스크롤은 현재 페이지 범위에서만 허용한다.
- 부모가 다른 중첩 요소나 다른 페이지는 유효한 대상으로 표시하지 않는다.
- 놓는 즉시 하나의 원자적 명령으로 적용하고 실행 취소 스택에 기록한다.

### 키보드와 버튼 대안

- Tab: 편집 가능한 블록 이동
- Space 또는 Enter: 블록 선택/이동 모드 진입
- `Alt+↑` / `Alt+↓`: 한 단계 앞/뒤로 이동
- `Alt+Home` / `Alt+End`: 페이지의 처음/끝으로 이동
- Escape: 이동 모드 취소
- 각 블록의 더보기 메뉴에 `앞으로`, `뒤로`, `맨 앞으로`, `맨 뒤로`를 제공해 단축키를 모르는 사용자도 사용할 수 있게 한다.

단축키는 WebView와 OS 충돌 여부를 구현 단계에서 확인하고, 충돌 시 키 조합을 조정한다.

### 오른쪽 Markdown 반영

- 이동을 놓는 즉시 Preview와 Source를 같은 새 결과로 갱신한다.
- 현재 보고 있던 의미적 블록을 안정적으로 식별해 가능한 한 스크롤 위치를 유지한다.
- Copy와 Save는 별도 캐시가 아니라 현재 정렬된 문서 모델에서 생성된 Markdown을 사용한다.
- 재생성 실패 시 기존의 마지막 유효 결과를 유지하고 `순서를 반영하지 못했습니다` 오류와 재시도 동작을 제공한다.

## 7. 용어와 안내 문구

| 기술 개념 | 사용자 표시 |
|---|---|
| Reading order | 읽기 순서 |
| Reorder | 순서 편집 / 앞으로 이동 / 뒤로 이동 |
| Struct Tree | 문서에 저장된 순서 |
| XY-Cut | 화면에 보이는 배치 |
| Reset override | 원래 순서로 |
| Top-level block | 문단 또는 콘텐츠 블록 |

주요 안내 문구:

- 빈 상태: `변환이 끝나면 읽기 순서를 확인할 수 있습니다.`
- 편집 불가: `이 결과에는 문단 위치 정보가 없어 순서를 편집할 수 없습니다.`
- 변경 완료: `이 페이지의 읽기 순서를 수정했습니다.`
- 내보내기 영향: `수정한 순서가 미리보기, 복사, 저장 파일에 반영됩니다.`
- 초기화: `이 페이지를 자동으로 감지한 순서로 되돌릴까요?`

## 8. 정합성의 핵심: 단일 문서 모델

현재 구현은 BBox JSON을 오버레이용 배열로 평탄화하고, Markdown은 별도의 `rawMarkdown` 문자열로 관리한다. 이 둘을 독립적으로 재배열하면 화면 번호만 바뀌고 실제 저장 결과는 바뀌지 않는 정합성 문제가 생긴다.

편집 기능 구현 전에 다음 단일 모델이 필요하다.

```text
변환 결과(JSON + Markdown 매핑)
        ↓
CanonicalDocument
  ├─ pages
  │   └─ ordered top-level blocks
  │       └─ nested children
  ├─ original order
  └─ user order overrides
        ↓
Markdown generator
        ↓
Preview / Source / Copy / Save / Outline / Search
```

원칙:

- PDF 오버레이는 모델의 위치 정보를 읽는다.
- Markdown은 모델의 현재 순서에서 결정적으로 생성한다.
- 모든 소비자가 같은 생성 결과 또는 같은 모델을 구독한다.
- 원본 JSON과 원본 자동 순서는 불변으로 보존한다.

## 9. 권장 데이터 모델

```ts
interface DocumentBlock {
  id: string;               // 현재 변환 결과 안에서 안정적인 ID
  sourcePath: number[];     // 예: kids[3].kids[1]
  pageNumber: number;
  type: BlockType;
  bbox: [number, number, number, number];
  content: string;
  children: DocumentBlock[];
}

interface PageOrder {
  pageNumber: number;
  originalBlockIds: string[];
  currentBlockIds: string[];
  revision: number;
}

interface ReorderCommand {
  pageNumber: number;
  blockId: string;
  fromIndex: number;
  toIndex: number;
}
```

### ID 규칙

- 화면 순번이나 배열 인덱스만 ID로 쓰지 않는다.
- 최초 변환 안에서는 `sourcePath` 기반 ID를 기본으로 사용할 수 있다.
- 재변환 후에도 편집을 복구해야 한다면 페이지, 형식, 정규화한 콘텐츠 해시, BBox 근사값을 조합한 fingerprint가 추가로 필요하다.
- fingerprint 일치가 불확실하면 자동 적용하지 않고 충돌 상태로 둔다.

### 사용자 변경 표현

전체 JSON 복사본을 수정하기보다 페이지별 순서 override를 저장한다.

```json
{
  "schemaVersion": 1,
  "documentFingerprint": "sha256:…",
  "pages": {
    "1": {
      "originalBlockIds": ["b6", "b7", "b8", "b9", "b10"],
      "currentBlockIds": ["b6", "b7", "b9", "b8", "b10"]
    }
  }
}
```

이 구조는 원본 보존, 페이지 초기화, 변경 여부 비교, undo 명령 생성을 단순하게 한다.

## 10. 저장 정책

### MVP 권장안

- 변경은 열린 문서 세션 동안 즉시 유지한다.
- Markdown 저장 시 현재 변경을 반영한다.
- PDF 원본과 변환 원본 JSON은 수정하지 않는다.
- 앱 재시작 후 편집 복원은 별도 기능으로 분리한다.

### 후속 영속화

- PDF 내용 fingerprint와 변환 프로필 fingerprint를 키로 로컬 앱 데이터에 override를 저장한다.
- PDF 파일명이나 경로만 키로 사용하지 않는다.
- 재변환 결과의 블록 집합이 달라지면 다음 셋 중 하나로 처리한다.
  1. 확실히 매칭된 변경만 복원
  2. 충돌 페이지를 표시하고 사용자 검토 요청
  3. 안전하게 override 무시

## 11. 구조별 처리 규칙

| 구조 | MVP 규칙 |
|---|---|
| Heading | 단일 블록으로 이동. 하위 섹션 전체를 자동으로 묶지 않음 |
| Paragraph | 단일 블록으로 이동 |
| Table | 표 전체를 한 블록으로 이동. 행·셀 순서는 편집 불가 |
| List | 목록 전체를 한 블록으로 이동. 항목 순서는 편집 불가 |
| Image | 이미지와 엔진이 같은 블록으로 제공한 캡션만 함께 이동 |
| Formula | 수식 블록 전체를 이동 |
| Footnote | 엔진이 paragraph로 준 경우 일반 문단처럼 취급하되 형식 개선은 후속 과제 |
| Header/Footer | 변환 설정에서 포함된 경우에만 편집 목록에 나타남 |

Heading 이동이 섹션 전체 이동처럼 오해될 수 있으므로, MVP 안내에는 `선택한 블록만 이동합니다`를 표시한다.

## 12. 상태와 예외 처리

### 상태 기계

```text
Unavailable → Viewing → Editing → Moving
                  ↑         ↓        │
                  └──── Exit ────────┘

Editing/Moving → Error (재생성 실패)
Error → Editing (재시도 또는 마지막 유효 상태 복원)
```

### 예외

- 변환 중: Order 편집 비활성화
- JSON만 있고 Markdown 매핑이 없음: 보기만 허용하고 편집 불가 이유 표시
- 블록이 하나뿐인 페이지: 편집 진입 불필요
- BBox가 없는 블록: 목록에서는 편집 가능하되 PDF 위 위치 표시가 없음을 알림. MVP에서는 구현 난이도에 따라 편집 제외 가능
- 문서 재변환: 저장하지 않은 변경이 있으면 명확히 알리고, 변환 완료 후 override 호환성을 검사
- undo 중 대상 블록 소실: 명령을 적용하지 않고 충돌 상태로 전환

## 13. 접근성 수용 기준

- 마우스 드래그 없이 전체 작업을 완료할 수 있다.
- 포커스 표시가 모든 배경에서 보인다.
- 스크린 리더가 `문단, 현재 8번째/10개, 9번째로 이동됨`처럼 위치 변화를 읽는다.
- 드롭 가능/불가능 상태는 색 외의 선, 아이콘, 텍스트로 구분한다.
- 확대 200%에서 핵심 동작이 가려지거나 잘리지 않는다.
- reduced motion 환경에서 위치 이동 애니메이션을 생략한다.

## 14. 구현 작업 묶음과 완료 조건

이 목록은 향후 병렬 실행을 위한 설계상 분해이며 현재 작업 범위에는 구현이 포함되지 않는다.

### A. CanonicalDocument와 안정 ID

- JSON 계층과 source path를 보존하는 문서 모델
- 페이지별 original/current order
- 중첩 자식이 부모와 함께 유지되는 불변식

완료 조건:

- fixture에서 원본 순서와 변경 순서를 독립적으로 조회할 수 있다.
- `6,7,8,9,10 → 6,7,9,8,10` 변환 단위 테스트가 통과한다.
- 중첩 표·목록 자식의 상대 순서가 변하지 않는다.

### B. 순서 명령과 이력

- move 명령
- undo 및 페이지 reset
- 변경 페이지 판정

완료 조건:

- 앞/뒤/처음/끝 이동과 잘못된 인덱스를 자동 테스트한다.
- undo와 reset 후 원본과 완전히 동일해진다.
- 페이지 밖 이동이 거부된다.

### C. Markdown 결정적 재생성

- 구조 블록별 Markdown 직렬화
- Preview/Source/Copy/Save 단일 결과 연결
- 기존 이미지 인라인, 수식, 표 출력 보존

완료 조건:

- 변경 후 네 소비자가 byte-equivalent Markdown을 사용한다.
- 순서 외의 콘텐츠가 바뀌지 않는 regression fixture가 통과한다.
- 재생성 실패 시 마지막 유효 Markdown이 보존된다.

### D. Order 편집 UI

- 보기/편집 모드
- PDF 오버레이 선택·드래그·드롭 표시
- 순서 목록 보조 UI
- 변경/초기화 상태

완료 조건:

- 대표 fixture를 포인터로 `6→7→9→8→10`으로 바꿀 수 있다.
- 50/100/150% 줌에서 대상과 표시가 일치한다.
- 다른 페이지와 중첩 자식은 drop target이 되지 않는다.

### E. 키보드·접근성

- 키보드 이동
- focus 관리
- live region 안내
- reduced motion

완료 조건:

- 키보드만으로 대표 fixture 교정·undo·reset이 가능하다.
- 이동 뒤 포커스가 같은 블록에 남는다.
- 자동 접근성 검사와 수동 screen-reader 체크리스트를 통과한다.

### F. 통합·회귀 검증

- Outline, search, scroll reference와의 정합성
- 대용량 문서 성능
- 재변환/취소/오류 경로

완료 조건:

- 변경된 heading 순서가 Outline에 일치한다.
- 검색 결과와 스크롤 이동이 올바른 블록을 가리킨다.
- 100페이지 문서에서 한 페이지 이동이 전체 PDF 재변환을 일으키지 않는다.
- 실기기 검증 전까지 자동 검증 완료와 보류 항목이 명확히 분리된다.

## 15. 기능 전체 수용 기준

1. 사용자가 알고리즘 용어를 몰라도 Order에서 편집 기능을 발견할 수 있다.
2. 한 페이지의 최상위 블록을 포인터와 키보드 양쪽으로 이동할 수 있다.
3. 대표 사례를 `6 → 7 → 9 → 8 → 10`으로 교정할 수 있다.
4. PDF 오버레이, Markdown Preview, Source, Copy, Save가 같은 순서를 사용한다.
5. 원본 자동 순서는 보존되며 undo와 페이지 reset이 가능하다.
6. 표·목록의 내부 구조와 페이지 경계는 손상되지 않는다.
7. 변환 재실행이나 재생성 오류가 있어도 마지막 유효 결과와 원본 순서를 잃지 않는다.
8. 키보드와 스크린 리더로 핵심 흐름을 수행할 수 있다.
9. 편집은 추출 엔진을 다시 실행하지 않는다.
10. 실기기 QA가 미완료인 경우 배포 판단 문서에 명시하며 자동 테스트 통과로 대체하지 않는다.

## 16. 리스크와 결정 필요 사항

| 항목 | 위험 | 권장 방향 |
|---|---|---|
| Markdown-JSON 매핑 | 현재 두 결과가 독립적이어서 블록 단위 재생성이 어려움 | UI보다 CanonicalDocument를 먼저 구현 |
| 안정 ID | 배열 인덱스는 재변환 시 깨짐 | source path + content/BBox fingerprint 분리 |
| Heading 의미 | 제목만 이동하면 섹션 의미가 달라질 수 있음 | MVP는 선택 블록만 이동한다고 명시하고 섹션 이동은 후속 |
| 겹치는 BBox | PDF 위 직접 선택이 어려움 | 순서 목록을 동등한 편집 표면으로 제공 |
| 영속화 충돌 | 재변환 후 오래된 override 오적용 가능 | MVP 세션 한정, 후속에서 보수적 매칭 |
| 장문 성능 | 전체 Markdown 반복 생성 비용 | 페이지/블록 기반 중간 표현과 부분 무효화 검토 |

## 17. 구현 시작 전 결정 게이트

다음 세 항목만 제품 결정으로 확정하면 MVP 구현을 시작할 수 있다.

1. 편집 내용을 앱 재실행 후에도 복원할지, MVP는 세션 한정으로 둘지
2. undo만 제공할지 undo/redo를 모두 제공할지
3. BBox가 없는 블록을 목록에서 편집 허용할지 제외할지

현재 권장 기본값은 `세션 한정`, `undo 우선`, `BBox 없는 블록은 목록에서만 편집 허용`이다.
